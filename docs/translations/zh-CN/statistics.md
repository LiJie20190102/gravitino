## 简介

统计信息是附加到表或其某个分区上的命名度量。行数、大小，
以及文件数量是显而易见的，你想记录的关于数据集的任何其他内容都可以放在
它们旁边。

统计信息是目录在不接触数据的情况下回答有关大小和形状的问题的方式。
这在联邦环境中最为重要，在此环境中，直接询问每个源系统意味着每个系统有不同的
机制。

## 快速开始

**1. 打开表。** 统计信息附加到表以及表的分区上。参见
[表和视图](./tables-and-views.md)。

**2. 阅读已有的内容。** 一些统计信息由 Gravitino 或源系统维护，
无需任何操作即可查看。

**3. 记录你自己的。** 自定义统计信息包含任何对你重要的度量，在一个名称之下，
由你来选择。

## 统计模型

### 保留和自定义

保留统计信息是指由 Gravitino 定义的统计信息，例如 `row_count`。该集合在未来
版本中可能会增加，因此保留名称不可供您自己使用。

自定义统计信息归你所有，其名称必须以 `custom.` 开头，以避免与任何内容冲突
Gravitino 可能会在未来保留。前缀是唯一的命名规则。

### 可修改与不可修改

统计信息会被标记为可修改或不可修改。由系统派生的统计信息，例如由
数据源维护的计数，是不应被手动覆盖的，Gravitino 会拒绝这种尝试，而不是
接受一个在下一次刷新时会被丢弃的值。

自定义统计信息是可修改的，因为没有其他对象维护它们。

### 值

值是有类型的，而不是自由文本，因此行数是一个数字，布尔值就是布尔值。
统计信息也可以存在但没有任何值，这意味着它是已知的，但当前未设置。

### 分区统计

统计信息附加到分区以及整个表，并且分区统计信息会被读取和
按范围写入，而不是一次一个。当表很大且被分区时，每个分区的
度量值使得裁剪和规划决策成为可能。

## 在 UI 中处理统计数据

目前统计数据未在 UI 中显示。对它们的读写通过 API 进行。

## 权限

统计信息归属于其所属的表。读取它们需要读取该表的权限，
而写入它们需要修改该表的权限。参见
[表和视图](./tables-and-views.md)。

## 使用 API

统计信息可以通过 REST 和 Java 客户端进行列出、设置和删除，针对表和
分区。端点、负载结构和操作示例位于
[管理统计信息](./manage-statistics-in-gravitino.md)。
