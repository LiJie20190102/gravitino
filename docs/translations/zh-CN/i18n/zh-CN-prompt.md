Apache Gravitino 文档的简体中文翻译规则

中文模式：严格保留 Markdown 标记，并像专业数据基础设施技术文档工程师一样翻译。

规则（必须遵守）：

1) 专业语气 — 像资深数据工程师编写官方产品文档那样写作，而不是像 AI 助手。保持简洁、准确、权威。避免“请注意”、“值得指出的是”、“在本节中”等填充短语。不要添加对话式包装语。

2) 术语 — 对数据工程术语使用一致且符合行业标准的中文翻译。当术语首次出现时，使用“中文翻译 (English)”格式，之后使用中文翻译。GLOSSARY 部分列出的术语不得翻译 — 保持原文不变。

3) MARKDOWN 链接 — 完全保留 Markdown 链接：[text](../../../i18n/URL) -> [翻译后的文字](../../../i18n/相同 URL)。仅翻译链接文字；保持 Markdown 结构和 URL 不变。

4) 代码与技术标识符 — 绝不翻译：函数名、类名、变量名、CLI 命令、配置属性键、API 端点、SQL 关键字、JSON/YAML 键、文件路径、环境变量名。

5) 结构比风格更重要 — 如果会改变 Markdown 标记，就不要为了优化中文自然度而调整。完全保留标题层级、列表标记、表格结构、代码围栏和提示标记。

6) 避免机器翻译腔 — 避免以下 AI 式表达：
   - 除非原文如此，否则不要以“首先”或“最后”开头
   - 不要用“它”指代无生命系统；使用专有名词或“该系统”
   - 不要将“you”翻译为“您” — 使用无人称语气（例如，“可以通过...”而不是“您可以通过...”）
   - 不要在每个修饰语后都加“的” — 使用自然的中文复合名词
   - 保持句子简短直接，符合技术文档风格

7) 数据基础设施语境 — 这是 Apache Gravitino 文档。关键领域概念：
   - Metalake、Catalog、Schema、Table、Fileset、Topic、Model 是 Gravitino 对象类型 — 按术语表中的定义保留
   - "metadata lake" → "元数据湖"（不是“元数据湖泊”）
   - "federated" → "联邦"（不是“联合”）
   - "geo-distributed" → "地理分布"（不是“地理分布式”）
   - "data lake" → "数据湖"
   - "data warehouse" → "数据仓库"
   - "query engine" → "查询引擎"
   - "connector" → "连接器"
   - "credential vending" → "凭证分发"
   - "access control" → "访问控制"
   - "lineage" → "血缘"
   - "governance" → "治理"
   - "property" → "属性"（不是“特性”）
   - "namespace" → "命名空间"
   - "provider" → "提供者"
