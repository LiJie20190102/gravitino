## 简介

标签是您在 metalake 中创建一次并附加到任意数量元数据的命名标签
对象。标签包含可选的注释和一组属性，因此它可以容纳少量的
除了其名称之外的结构化细节。同一个标签可以同时附加到 catalog、table 和单个
column 上。

标签随元数据而非数据一起传递，因此应用于表的标签对
通过 Gravitino 访问该表的每个引擎和每个客户端都是可见的，无论哪个系统
实际存储它。这使得标签成为一种实用的方式，可以一次性对同时存在于
多个目录中的元数据进行说明。

Gravitino 存储标签，沿元数据层次结构向下解析它们，并在对象
出现的任何地方显示它们。常见用途：

- 在 catalog 或 schema 上记录一次分类，并让每个表和列
其下的都带有该分类，无需进一步操作
- 回答跨您不拥有的 catalog 的覆盖范围问题，例如哪些对象在
metalake 的任意位置被标记为个人数据
- 将从另一个 catalog 到达的分类传递给引擎和客户端，这些引擎和客户端
从 Gravitino 读取元数据
- 标记对象以供下游消费者采取行动，例如一个作业读取对象上的标签
在决定如何处理它之前

## 快速开始

**1. 创建标签。** 标签是在 UI 的标签列表中创建的。标签需要一个名称，并且可以
携带注释以及您希望随其保留的任何属性。

**2. 将其附加到对象。** 打开要标记的 catalog、schema 或 table 并添加 tag
从其 tag 控件中。仅提供 metalake 中已存在的 tag，因此请创建 tag
先创建，然后再附加。

**3. 标记单个列。** 表格的列列表在每一行上都有其自己的标签控件，因此一个
标签可以位于某一列上，而不应用于表格的其余部分。

**4. 查看标签附加在何处。** 在标签列表中选择一个标签名称会显示它所
直接附加到的对象。

## 标签模型

### 什么可以携带标签

元数据对象由类型和名称标识，目录以下的每个层级由
点号分隔。九种对象类型可以带有标签。

| 对象类型 | 名称形式                                                 |
|-------------|-----------------------------------------------------------|
| `CATALOG`   | `{catalog_name}`                                          |
| `SCHEMA`    | `{catalog_name}.{schema_name}`                            |
| `TABLE`     | `{catalog_name}.{schema_name}.{table_name}`               |
| `VIEW`      | `{catalog_name}.{schema_name}.{view_name}`                |
| `COLUMN`    | `{catalog_name}.{schema_name}.{table_name}.{column_name}` |
| `FILESET`   | `{catalog_name}.{schema_name}.{fileset_name}`             |
| `TOPIC`     | `{catalog_name}.{schema_name}.{topic_name}`               |
| `MODEL`     | `{catalog_name}.{schema_name}.{model_name}`               |
| `FUNCTION`  | `{catalog_name}.{schema_name}.{function_name}`            |

metalake 无法携带标签，因此没有单一的附加点可以一次性覆盖所有内容
。要访问 catalog 中的每个对象，请将标签附加到 catalog 上。

UI 会为目录、架构、表和列附加标签。对于其他类型，请使用
本页末尾描述的 REST API。

### Names, Properties, and Assignment Values

标签名称在其 metalake 中是唯一的，并且是在其他所有地方使用的标识符，因此重命名一个
标签会改变每个存储的请求必须请求的内容。

名称最多包含 64 个字符，由字母、数字、下划线、斜杠、等号和连字符组成。
诸如 `pii/email` 这样的分隔符约定能让不断增长的集合保持可读性。

属性是位于标签本身而不是附件上的自由格式键值对，所以
每个携带该标签的对象都会看到相同的值。属性适合用于描述关于标签的事实，例如
哪个团队拥有它或它来自哪个外部系统。属性不适合用于描述关于单个
被标记对象的事实。

Assignment values describe one tag on one object. For example, the same `data_domain` tag can have
the value `finance` on one table and `risk` on another. An assignment can have no value, one value,
or several values. Adding a value is incremental, so adding `risk` to an assignment that already has
`finance` leaves both values in place.

创建标签时，您可以选择三种值约束之一：

| 约束     | 含义                                                                        |
| -------------- | ------------------------------------------------------------------------------ |
| 任意值      | 该标签接受任何非空字符串，也可以不带值赋值 |
| 无值       | 该标签只能不带值赋值                                   |
| 允许的值 | 该标签仅接受配置列表中的值                           |

值是区分大小写的字符串，最多 256 个字符。此约束在
创建标签后无法更改。标签属性和分配值是相互独立的：更改属性会影响
所有位置的标签，而更改分配值仅影响该对象。分配值
目前通过 REST API 或 Java 和 Python 客户端进行管理。

### 继承

一个对象会显示附加在其上的标签以及附加在其每个祖先上的标签，因此一个标签
在目录上会出现在其下的每个模式、表和列上。对于支持
多级模式的目录，中间模式也是祖先，因此向下两级的模式
会继承其上方的两个模式。

每个标签出现一次，无论它是通过一个还是多个祖先到达该对象。附加的标签
直接附加到对象上的也算作直接，即使其祖先也带有该标签。

赋值遵循相同的继承路径。如果子节点没有针对某个标签的直接赋值，
它会从最近的有效祖先接收值。子节点上的直接赋值
会覆盖该标签的继承赋值；其值不会与祖先的值合并。
例如，分配了 `data_domain = risk` 的表仅显示 `risk`，即使其目录被
分配了 `data_domain = finance`。

这两者是可以区分的。在 UI 中，继承的标签会标有锁图标。通过 REST，标签
使用 `details=true` 请求的列表会在每个标签上包含一个 `inherited` 字段，而普通的列表
名称列表则没有。

仅通过继承到达对象的标签无法在那里移除。将其从
携带它的祖先中分离，这也会影响该祖先下的所有其他对象。

继承是在读取对象时解析的，而不是存储在对象上，因此附加一个
标签到目录会立即对之后创建的表生效。

## 在 UI 中使用标签

### 管理标签集

标签列表包含 metalake 中的每个标签及其注释和创建时间，并且可以
进行搜索。标签可以被重命名，并可在其中编辑其注释和属性。

删除标签会将其从所有附加了该标签的对象中移除。系统不会警告受此影响的
对象数量，且无法恢复附加关系，因此请检查标签的使用位置，然后再
删除标签。

### 附加与分离

标签是从对象端附加的，而非从标签端附加的，因此打开目录、架构或表并使用
其中的标签控件。继承的标签没有移除控件。取消附加仅移除直接
附加，因此对象仍会显示它从祖先继承的标签。

列标签在表页面的列列表中进行编辑。一列显示其自身的标签以及
它从其上方的表、模式和目录继承的所有内容，这通常是所列内容的
大部分。

### 查找标签的使用位置

选择标签名称会打开一个视图，列出直接附加该标签的对象。继承的
范围不包括在内，因此附加到某个目录的标签会列出该目录，而不是
其下的表。跨越子树的覆盖范围问题是通过遍历对象并读取
每个对象上的标签来解答的。

## 权限

标签权限保留在标签上，并且除了对被
标记对象的权限之外还适用。

| 权限    | 可授权对象              | 允许的操作                              |
|--------------|---------------------------|---------------------------------------------|
| `CREATE_TAG` | Metalake                  | 在 metalake 中创建标签               |
| `APPLY_TAG`  | Metalake，或单个标签 | 读取标签并将其附加或分离 |

修改和删除标签仅限 metalake 所有者和标签所有者。
附加标签还需要对被标记对象的访问权限，因此可以应用标签的用户
无法借此访问他们原本无法看到的对象。标签列表仅显示
允许用户读取的标签。

## 使用 API

标签可以通过 REST 以及 Java 和 Python 客户端进行创建、附加和读取，这也是
目前为视图、文件集、主题、模型和函数添加标签的唯一方式。端点、负载
结构和操作示例请参见 [管理标签](./manage-tags-in-gravitino.md)。
