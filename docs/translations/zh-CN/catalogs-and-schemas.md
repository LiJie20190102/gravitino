## 简介

目录是到持有数据或元数据的系统的连接，模式是其中的
命名空间。两者共同构成 Metalake 与实际操作对象之间的
两层。

目录是联邦发生的层级。注册目录会告知 Gravitino 如何连接 Hive
metastore、Iceberg REST catalog、MySQL 数据库、Kafka 集群或对象存储，此后
其中的对象与 Metalake 中的其他对象并列呈现。Gravitino 不
复制这些对象。列出模式时查询源系统，因此所见即当前实际内容。

模式是中间层级，其含义取决于底层系统。在关系型
目录中它是数据库。在文件集目录中它将文件集组织在某个位置下。在模型
目录中它是模型的命名空间，没有物理对应物。

目录和模式都承载标签和策略，当需要广泛应用时，两者都是附加标签和策略
的层级。目录上的标签会覆盖其下的每个对象。

## 快速入门

**1. 创建目录。** 目录通过 UI 中的目录列表或 REST 创建。目录
需要名称、类型，大多数类型还需要提供者，以及告知 Gravitino
如何连接的属性。

**2. 创建或发现模式。** 连接到现有系统会呈现其中已有的
模式。通过 Gravitino 创建模式时，如果源
系统支持，也会在源系统中创建。

**3. 操作其中的内容。** 表、文件集、主题、模型和函数都位于
模式之下，无论由哪个系统存储，访问方式相同。

## 目录模型

### 目录类型与提供者

每个目录都有一个类型，决定了其中存放的对象种类。

| 类型         | 包含            |
|--------------|-----------------|
| `RELATIONAL` | 表和视图        |
| `FILESET`    | 文件集          |
| `MESSAGING`  | 主题            |
| `MODEL`      | 模型            |

大多数类型还需要提供者，即所连接系统的名称：`hive`、
`lakehouse-iceberg`、`jdbc-mysql`、`kafka` 等。文件集目录和模型目录是例外。
Gravitino 自行管理其元数据，因此类型即可确定，提供者会被自动推断。

每个提供者有其自身的连接属性和描述页面。

### 名称与属性

目录名称在其 Metalake 内唯一，模式名称在其目录内唯一。

属性承载连接详情，哪些属性适用完全取决于提供者。两个
保留键在所有位置行为一致。`in-use` 记录目录是否可用并
默认为 `true`。`location` 设置目录类型使用时的基础路径。

### 使用中与未使用

未使用的目录只能被列出、加载、启用或删除。所有其他
对其或其中任何对象的操作都会失败，这使得禁用成为一种在不移除
其元数据的情况下使连接停服的方式。

禁用目录不会影响源系统。它指向的表和文件保持在
原位。

## Gravitino 存储的内容

Gravitino 存储目录注册信息、通过它创建的模式和对象，以及
附加在这些对象上的内容如标签、策略和所有权。它不存储
源系统内容的副本。

列出模式中的表会在请求时访问源系统，因此直接在
Hive 中创建的表会在下次查询 Gravitino 时出现。需要了解的是，Gravitino
无法回答尚未被查询过的对象的问题。

## 在 UI 中操作目录和模式

目录列表包含当前 Metalake 中的所有目录。可以在其中创建、编辑、
启用或禁用以及删除目录，每个目录可展开为其模式及其
内容。

标签和策略从目录和模式行附加，这是对
整个子树进行分类的最快方式。

## 删除目录和模式

删除操作受保护，强制删除会改变行为。

不使用强制删除时，目录必须没有模式，模式必须没有对象。任一条件
不满足都会使请求失败，而不会删除任何内容。

使用强制删除时，Gravitino 移除注册信息及其持有的所有内容信息。对于
托管对象，如托管文件集或模型，这也会删除数据。对于联邦
对象，Hive 表或 S3 文件保持在原位，仅 Gravitino 中的记录被移除。

## 权限

| 权限            | 可授予范围                     | 允许的操作                             |
|------------------|-------------------------------|---------------------------------------|
| `CREATE_CATALOG` | Metalake                      | 在 Metalake 中创建目录                 |
| `USE_CATALOG`    | Metalake 或目录                | 访问目录及其内容                       |
| `CREATE_SCHEMA`  | Metalake、目录或模式           | 创建模式                               |
| `USE_SCHEMA`     | Metalake、目录或模式           | 访问模式及其内容                       |

在更大范围内授权会覆盖其下的所有内容，因此在 Metalake 上授予 `USE_CATALOG` 可访问
其中的每个目录。

修改和删除目录或模式是 Metalake 所有者和对象所有者的权限。
所有权沿层级向下传递，因此目录的所有者拥有对其下所有内容的
所有者权限路径。

## 使用 API

目录和模式可通过 REST 和 Java、Python 客户端创建、列出、修改和删除。
端点、请求负载结构和工作示例见
[管理目录和模式](./manage-catalogs-and-schemas.md)。
